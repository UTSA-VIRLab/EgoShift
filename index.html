A model can score well without looking at the image

When a question states a camera turn, that turn alone rules out some answers. A predictor given only the stated action already beats chance by a wide margin — and balanced answers, text-only arms and human references do not catch it, because none of them is conditioned on the action.

The audit is not hypothetical. An earlier build of our own data was balanced by the usual standard. A predictor that saw only the stated turn scored 72.3% on it.

EgoShift makes the shortcut a quantity instead of a worry. The camera geometry determines which answers each turn can produce, so the highest score reachable from the action alone can be computed before any model is run. We derive that ceiling and build every turn to sit exactly on it.

Pooled accuracy hides the failure

Across 36 systems, accuracy does not fall as the turn grows larger. It collapses at exactly two turns.

How the ceiling is computed

Write z = (r, d) for the stated turn, r its size and d its direction. Five sizes and two directions give ten cells. A predictor given z and nothing else — no image, no scene, no object, no wording — can do no better than answering the commonest answer in each cell. With S(z) the answers the geometry allows and nz the questions in cell z:

Cmin  =  (1/N) · Σz  ⌈ nz / |S(z)| ⌉

Two independent implementations compute S(z) — an interval derivation and a dense enumeration — and a build is accepted only when they agree and every cell attains the bound. Balancing answers across the whole set does not achieve this, which is exactly why the earlier 72.3% build looked fine.

What the ceiling does not do. It bounds one shortcut: answering from the stated turn with no image. It says nothing about wording, metadata, or a cue some future model finds. We do not claim the questions are free of shortcuts in general.

Get started

git clone https://github.com/UTSA-VIRLab/EgoShift.git
cd EgoShift
python -m pip install -e .
make check

Score predictions, then audit a split against the geometry:

egoshift score --questions sample/questions.jsonl \
               --predictions sample/predictions.jsonl

egoshift audit-taskb --questions path/to/taskb_questions.jsonl

Scoring and auditing need no simulator. See installation, getting started, data and the FAQ.

Reporting results

Report accuracy per stated turn, not pooled. Progress on EgoShift should appear as higher scores at 90° and 180°. A system that raises its pooled score while leaving those at the action-only ceiling has not improved at the thing the benchmark measures.
