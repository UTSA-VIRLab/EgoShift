A stated turn gives the answer away.

Ask where an object lands after a 90° turn and the turn alone has already ruled out some answers. EgoShift computes how much is given away — from camera geometry, before any model runs — and builds every question to sit exactly on that bound.

The contribution is the construction, not the scores

The bound above is not measured from model behaviour. It is computed from the camera geometry before any model runs, so it cannot be tuned to suit a result — and every question in the benchmark is built to sit on it.

What the test does

For each stated turn we derive the highest score a predictor can reach from the turn alone, with no image. Five angles and two directions give ten groups, and each one is built to match that value exactly.

We release the derivation, an independent checker and a record of which scenes were ever used during development.

Why balancing is not enough

An earlier build of our data passed every conventional balance check, yet a system that saw only the stated turn scored 72.3% on it. The imbalance sits inside each turn, not across the whole question set.

That build differs from the released one in other ways, so the number shows what the test catches — not a controlled measure of what the construction changed.

Three tasks, one shared geometry

Task A

Is it the same object?

Two views of one room, a box drawn in each. A control, not a difficulty claim.

Task B — primary

Where is it after you turn?

One view, a stated in-place turn, and the question of where the object lands. The only task whose question names an action.

Task C

Can you still see it?

Visible, out of view, or occluded, after the camera has moved.

Where the bound comes from

Every Task-B image is taken at standing height with a fixed tilt and field of view, and the stated turn is a rotation about the vertical axis from that same spot. Only the heading changes.

Because the geometry is declared, the set of answers a turn can produce is finite and can be computed exactly. The construction requires the object's centre to start within 66.5868° of straight ahead — the horizontal half-angle of a 640×480 frame at a 120° vertical field of view, written into the build before any pose was replayed.

Two independent implementations compute that answer set and agree on all ten cells. The held-out set meets the bound in every one, holding the shortcut to 45.90%.

Run it

The public artifact holds the questions for every split, the development answers, the construction and audit tools, and every raw model response behind the paper's tables. Only the held-out answer key is withheld.

git clone https://github.com/UTSA-VIRLab/EgoShift.git
cd EgoShift && pip install -e ".[full]"
egoshift audit-taskb --questions taskb_questions.jsonl

If you report results

  • Report Task B one turn at a time and Task C one answer class at a time.
  • Compare each score against the random rate, that turn's action-only bound, and the trained-human reference.
  • A score above the bound is necessary but not sufficient — a system can reach it without using the image.
  • Treat questions from the same room as dependent, and do not tune on the held-out questions.
